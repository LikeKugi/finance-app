# План: формы быстрого добавления на «Главной»

Статус: реализовано (код, тесты и документация обновлены; базовые проверки `cargo fmt`, `cargo check`, `cargo clippy` и `cargo test --workspace` выполнены). Описание опирается на фактическое состояние репозитория:
`crates/ui/src/gpui/home.rs`, `shell.rs`, `transactions.rs`, `transfers.rs`, `support.rs`,
`crates/db/src/lib.rs`, `docs/home-page-plan.md`, `docs/form-guidelines.md`,
`docs/page-actions-and-filters.md`, `AGENTS.md`.

## 1. Цель

Заменить на вкладке «Главная» секцию «Быстрые действия» (три кнопки: «Добавить доход»,
«Добавить расход», «Добавить перевод») двумя встроенными компактными формами:

1. **Добавление дохода** — строка 1: поле суммы + кнопка сохранения; строка 2: Валюта, Категория,
   Зачислить на карту.
2. **Добавление расхода** — строка 1: поле суммы + кнопка сохранения; строка 2: Валюта, Категория,
   Зачислить на карту (подпись «Оплачено картой»), Место траты.

Записи создаются сразу со страницы, без перехода на вкладку операции и без модального диалога.

## 2. Исходное состояние (до изменений)

- `home.rs` — только данные и чистые функции: `HomeAction` (8 переходов + `NewIncome`, `NewExpense`,
  `NewTransfer`), `home_action_tab`, `HomeLink`, `QuickAction`, `described_sections()`,
  `all_page_links()`, `quick_actions()` и три теста.
- `AppShell` (`shell.rs`) — сущность; `render_home` рисует заголовок, сообщение, «Быстрые действия»
  (кнопки `.primary().large()` с `IconName::Plus`), секции «Разделы» и «Все страницы».
- Быстрые действия открывают модальную форму существующей страницы: `TransactionsPage::create_new`
  и `TransfersPage::create_new` (`open_form` → `Dialog` 800 px).
- Логика суммы в форме операции: `InputState` с плейсхолдером «например: 100 + 20 - 5 * 2 / 4»,
  разбор `finance_core::parse_amount_expression`, предпросмотр «Итого: {sum}», предупреждение
  `support::DIVISION_ROUNDING_WARNING` при делении.
- Селекты формы: `Select` + `Entity<SelectState<Vec<SharedString>>>` (`choice()`), выбор карты
  ограничен картами в валюте операции (`eligible_cards`), варианты карты начинаются с «Без карты»,
  места траты — с «Не указано».
- Сохранение: `finance_db::save_transaction_with_card_and_rate_effect_and_place(...)`.
- Доступность «Добавить перевод» считается в `AppShell::refresh_transfer_availability`
  (`can_create_transfer`).

## 3. Принятые решения

| Решение | Значение |
|---|---|
| Размещение | Вместо секции «Быстрые действия» — две панели в одной строке с переносом по ширине (`flex_wrap`, gap 16 pt), каждая ~600 pt при 1280 px |
| Заголовки панелей | «Добавление дохода», «Добавление расхода» (18 pt, полужирный), как у секций ниже |
| Поле суммы | `Input` размера Large (`Sizable::large`), тот же `InputState`, плейсхолдер и разбор выражений, что в форме операции; предпросмотр «Итого» и предупреждение о делении — под строкой |
| Кнопка сохранения | `Button` размера Large, только иконка `IconName::Check`, варианты `.success()` + `.outline()` (доступны в gpui-component 0.10.0); без текста |
| Селекты | `Select` размера XSmall (`.xsmall()`), подписи над полями 12 pt по `docs/form-guidelines.md` |
| Источник данных | `list_categories(kind, true)`, `list_expense_places`, `list_payment_documents(...)`; загрузка при активации вкладки, не на кадре отрисовки |
| Дата | **Согласовано:** сохраняется текущая дата («сегодня», `Local::now().date_naive()`), поля даты в форме нет; у поля суммы — мелкая подпись «Дата: сегодня (ДД.ММ.ГГГГ)». Запись с другой датой правится на странице операции |
| Комментарий | Пустая строка (поля в форме нет); при необходимости запись правится на странице операции |
| Влияние на ставку вклада | `affects_deposit_rate = false`, как при создании новой операции из существующей формы |
| Валюта по умолчанию | RUB (`Currency::Rub`), как в `open_form` |
| Категория по умолчанию | Первая активная категория своего вида (`category_tree_labels`); если активных нет — сохранение недоступно с пояснением |
| Карта по умолчанию | «Без карты»; при смене валюты выбор карты сбрасывается |
| Место траты | «Не указано» (только форма расхода) |
| После сохранения | Сумма очищается, выбор селектов сохраняется; показывается подтверждение («Доход добавлен» / «Расход добавлен»); страницы операций обновляются при переходе на вкладку (`AppShell::activate`) |
| Итоги и аналитика | На «Главной» не показываются: семантика «На руках»/«Баланс» не определена (`AGENTS.md`, 9.4) |
| Миграции и БД | Не требуются; изменения только в `finance-ui` |

## 4. Что изменено в коде

### 4.1. Новый модуль `crates/ui/src/gpui/quick_forms.rs`

- `pub(crate) struct QuickTransactionForm` — GPUI-сущность одного вида операции (`TransactionKind`):
  `amount: Entity<InputState>`, `currency: Option<Currency>` + `currency_select`,
  `categories: Vec<Category>` + `category_ids`/`category_id` + `category_select`,
  `cards: Vec<PaymentDocument>` + `card_ids`/`card_id` + `card_select`,
  `places: Vec<ExpensePlace>` + `place_ids`/`place_id` + `place_select` (только расход),
  `message: Option<(String, bool)>`, `saved: Option<String>`, `_subscriptions`.
- `new(database, kind, window, cx)` — создание состояний ввода и пустых селектов.
- `reload(&mut self, window, cx)` — загрузка справочников (категории, места, карты) и перестройка
  селектов; ошибка чтения показывается текстом, а не маскируется.
- `impl Render` — две строки панели по разделу 1: Large-инпут + Large-кнопка с `Check`; строка
  селектов XSmall с подписями; под формой — «Итого», предупреждение о делении, ошибка и успех.
- `save(&mut self, cx)` — та же семантика, что в `TransactionsPage::save`: обязательные категория
  и валюта, разбор суммы выражением, пустой комментарий, `affects_deposit_rate = false`,
  сохранение введённых значений при ошибке, вызов
  `finance_db::save_transaction_with_card_and_rate_effect_and_place`.
- Чистые функции для модульных тестов: разбор суммы, список допустимых карт по валюте,
  соответствие подписи селекта идентификатору, сброс карты при смене валюты, признак «можно ли
  сохранять» (есть активная категория).

### 4.3. `crates/ui/src/gpui/home.rs`

- Удалить из `HomeAction` варианты `NewIncome`, `NewExpense`, `NewTransfer` и соответствующие ветки
  `home_action_tab` (для переводов остаётся `OpenTransfers`).
- Оставить описания разделов, ссылки на все страницы и тесты

### 4.4. `crates/ui/src/gpui/shell.rs`

- Поля `AppShell`: `income_form: Entity<QuickTransactionForm>`,
  `expense_form: Entity<QuickTransactionForm>`; создать их в `run` рядом со страницами.
- Удалить `transfer_available`, `home_message`, `refresh_transfer_availability` и импорт

- Использовать перенесённые в `support.rs` функции (`card_label`, `eligible_cards`,
  `expense_place_label`); поведение существующей формы не менять.

## 5. Тесты

`quick_forms.rs` (модульные, рядом с кодом):

- разбор суммы: «100 + 20 - 5 * 2 / 4» даёт ожидаемое значение; пустая строка и «не число» — ошибка;
  деление помечается предупреждением;
- карты, доступные для выбора, — только совпадающие по валюте; смена валюты сбрасывает карту;
- подписи селектов однозначно соответствуют идентификаторам категории, карты и места траты;
  «Не указано» и «Без карты» дают `None`;
- сохранение невозможно без активной категории и без валюты; при ошибке значения не теряются;
- подпись даты формируется из переданной даты чистой функцией (без обращения к часам в тестах);
- у формы расхода есть место траты, у формы дохода — нет.

`home.rs` — обновить тесты после удаления быстрых действий.
`shell.rs` — тест вкладки «Главная» без изменений.

Ручная проверка: запуск `cargo run -p finance-app`, создание дохода и расхода с главной, появление
записей на вкладках «Доходы»/«Расходы» после перехода, поведение при отсутствии активных категорий

## 8. Открытые вопросы и риски

1. **~~Дата операции.~~ Решено (см. раздел 3):** сохраняется текущая дата; около поля суммы показывается
   фактическая дата, чтобы пользователь видел, какая дата попадёт в запись. Дату вычисляет вызываемый
   код формы (`Local::now().date_naive()`), а чистые функции проверки остаются тестируемыми без
   обращения к часам.
2. **Подпись селекта карты в расходе. Решено:** у расхода «Оплачено картой», у дохода
   «Зачислить на карту», по смыслу операции и по возможному списанию с дебетовой карты.
3. **Переводы. Решено:** кнопка «Добавить перевод» удалена с «Главной», создание перевода
   остаётся доступным на вкладке «Переводы» через кнопку «Добавить».
4. **Списание с карты и `affects_deposit_rate`.** Компактная форма не содержит этих признаков:
   для расхода списание выполняется по логике БД, влияние на ставку вклада — `false`. Если нужно
   включать влияние на ставку, форме потребуется дополнительный элемент.
5. **Обновление данных на других вкладках.** Списки обновляются при переходе на вкладку;
   мгновенная перезагрузка потребовала бы дополнительных запросов к БД.
6. **1280 × 720.** Две панели по ~600 pt и четыре XSmall-селекта в строке проверяются запуском;
   при нехватке ширины — перенос панелей и селектов без горизонтальной прокрутки.
