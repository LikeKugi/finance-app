# План: форма быстрого добавления на «Главной»

Статус: реализовано. Код, тесты и документация обновлены; выполнены `cargo fmt`, `cargo check --workspace --all-targets --locked`, `cargo clippy --workspace --all-targets --locked -- -D warnings` и `cargo test --workspace --locked`. Описание опирается на фактическое состояние `crates/ui/src/gpui/quick_forms.rs`, `shell.rs`, `docs/form-guidelines.md`, `docs/page-actions-and-filters.md`, `docs/decisions.md`, `AGENTS.md`.

## 1. Цель

Заменить две компактные панели добавления дохода и расхода на вкладке «Главная» одной вертикальной формой, отцентрованной по горизонтали. Записи создаются сразу со страницы, без перехода на вкладку операции и без модального диалога.

## 2. Исходное состояние (до изменений)

- `quick_forms.rs` содержал сущность `QuickTransactionForm` для одного `TransactionKind`; в `AppShell` хранились два экземпляра: `income_form` и `expense_form`.
- Каждая панель шириной 600 pt показывала заголовок «Добавление дохода» или «Добавление расхода», строку «Large-инпут + Large-кнопка только с иконкой `Check`» и строку XSmall-селектов.
- Селекты: валюта, категория, карта («Зачислить на карту» у дохода, «Оплачено картой» у расхода) и место траты только у расхода.
- Сущность формы, разбор суммы, проверки и сохранение через `finance_db::save_transaction_with_card_and_rate_effect_and_place` уже существовали; менялась только компоновка и управление типом операции.

## 3. Принятые решения

| Решение | Значение |
|---|---|
| Размещение | Одна форма шириной 480 pt в центре страницы по горизонтали; ниже сохраняются секции «Разделы» и «Все страницы» |
| Заголовок | «Добавление» (18 pt, полужирный), без указания типа в заголовке |
| Поле суммы | `Input` размера Large на всю ширину формы; тот же `InputState`, плейсхолдер и разбор `parse_amount_expression`, предпросмотр «Итого» и предупреждение о делении под формой |
| Кнопка сохранения | `Button` Large, зелёный `.success()` без `.outline()`, текст «Добавить» и иконка `IconName::CircleCheck`, на всю ширину формы |
| Переключатель типа | `ButtonGroup` в одну строку с кнопками «Доход» и «Расход»; активна ровно одна, состояние берётся из `self.kind`, выделенная кнопка получает стиль `info` (`btn-info`) |
| Смена типа | Сбрасывает категорию и карту, очищает сообщения и перезагружает справочники для нового типа; введённая сумма сохраняется |
| Селекты | `Select` Small (`.small()`) на всю ширину формы (`.w_full()`), вертикально, подписи над полями; валюта, категория, «Зачислить на карту» и, только для расхода, «Место траты» |
| Подпись карты | «Зачислить на карту» в обоих режимах по прямому требованию; на страницах операций подпись по смыслу операции не изменена |
| Источник данных | `list_categories(kind, true)`, `list_expense_places`, `list_payment_documents(...)`; для дохода только дебетовые карты; загрузка при активации вкладки и при смене типа, не на кадре отрисовки |
| Дата | Текущая (`Local::now().date_naive()`), показывается подписью у поля суммы; поля даты в форме нет |
| Комментарий и ставка | Пустой комментарий, `affects_deposit_rate = false`, как при создании операции на её странице |
| Валюта и категории по умолчанию | RUB; первая активная категория выбранного вида; «Без карты» и «Не указано» как пустые варианты |
| После сохранения | Сумма очищается, остальные выборы сохраняются; показывается «Доход добавлен» или «Расход добавлен» |
| Итоги и аналитика | Не показываются: семантика «На руках»/«Баланс» не определена (`AGENTS.md`, 9.4) |
| Миграции и БД | Не требуются; изменения только в `finance-ui` |

## 4. Что изменено в коде

### 4.1. `crates/ui/src/gpui/quick_forms.rs`

- `QuickTransactionForm::new(database, window, cx)` больше не принимает `TransactionKind`; по умолчанию активен доход.
- Добавлен `set_kind(kind, window, cx)`: exclusive-переключение с перезагрузкой справочников; `selected_kind(&[usize])` проверяет, что выбрана ровно одна кнопка.
- `reload` вызывает `cx.notify()` после перестройки селектов.
- `impl Render` строит одну вертикальную форму по разделу 3; селекты для расхода включают место траты.
- `save` сохраняет прежнюю семантику: обязательные категория и валюта, точный разбор суммы, текущая дата, пустой комментарий, списание с карты по логике БД, `affects_deposit_rate = false`.
- Общая подпись карты вынесена в `CARD_FIELD_LABEL`; старая функция `card_field_label(kind)` удалена.

### 4.2. `crates/ui/src/gpui/shell.rs`

- В `AppShell` одно поле `quick_form: Entity<QuickTransactionForm>` вместо `income_form` и `expense_form`.
- `activate(PageTab::Home)` перезагружает одну форму; `run` создаёт её один раз.
- `render_home` оборачивает форму в контейнер `w_full().flex().justify_center()`.

## 5. Тесты и проверки

Модульные тесты `quick_forms.rs`: общая подпись карты, exclusive-выбор типа (`[0]`, `[1]`, пусто и два индекса), разбор суммы, соответствие подписи селекта идентификатору, блокировка сохранения без категории или валюты. Остальные тесты workspace не менялись.

Фактически выполнены: `cargo fmt --all`, `cargo check --workspace --all-targets --locked`, `cargo clippy --workspace --all-targets --locked -- -D warnings`, `cargo test --workspace --locked` (84 теста `finance-db`, 101 тест `finance-ui`, 0 failures). Отладочное приложение запускалось без сообщений в логе; захват экрана в этом окружении недоступен (`could not create image from display`), поэтому визуальная проверка 1280×720 и Windows-сборка не выполнялись.

## 7. Ограничения и вопросы

1. При смене типа сбрасываются категория и карта, чтобы не перенести выбор из другого справочника.
2. Подпись «Зачислить на карту» для расхода используется по прямому запросу; на странице расходов сохранена подпись «Оплачено картой».
3. Списки других вкладок обновляются при переходе на них.
4. Миграция и резервная копия не требуются: схема БД и финансовые правила не менялись.
