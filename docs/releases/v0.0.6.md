# FinanceApp v0.0.6 — следующий платёж и справочники

**Дата:** 22 ноября 2026  
**Тег для публикации:** `v0.0.6` (совпадает с версией в `../../crates/app/Cargo.toml`)  
**Диапазон изменений:** `1cc123ce...94e4d44`

FinanceApp — локальное настольное приложение для личных и семейных финансов. В выпуск `0.0.6` вошли функция «Следующий платёж» для платёжных документов, поле «Размер следующего платежа» в схеме БД, а также существенное улучшение формы категорий справочников с подсказками иерархии.

## Что нового

### Следующий платёж

- В таблицу платёжных документов добавлена колонка «Следующий платёж» с датой и суммой.
- Реализован диалог и форма «Следующий платёж»: при выборе карты пользователь видит дату следующего платежа и может зафиксировать сумму.
- Добавлена иконка-кнопка `Inspector` в колонку действия для быстрого перехода к форме следующего платежа.
- Ширина колонок действия и следующего платежа настроена так, чтобы содержимое не обрезалось при стандартном разрешении.
- Сортировка колонок таблицы обновлена: поддерживается сортировка по дате следующего платежа.
- Заголовок группы «Следующий платёж» выделен визуально, чтобы отделить эту информацию от остальных полей карты.

### Размер следующего платежа

- Миграция `V13__payment_document_next_payment.sql` добавляет колонку `next_payment_amount` в таблицу `payment_documents`.
- Поле хранится как `TEXT` с SQL-проверкой формата: только корректные десятичные числа без ведущих/конечных точек и лишних символов.
- Поле опционально: `NULL` для дебетовых карт и для случаев, когда сумма заранее неизвестна.
- Значение участвует в форме платёжного документа и отображается в таблице наряду с датой платежа.

### Справочники — категории

- Форма редактирования категории получила улучшенный выбор родительской категории: вместо простого списка строк используется компонент `Select` с типизированными элементами `ParentCategoryItem`.
- Каждый элемент выпадающего списка родительских категорий показывает tooltip с полным названием, что упрощает навигацию по глубокой иерархии.
- Добавлена поддержка фильтрации по категории в транзакциях: при выборе категории в фильтре отбираются операции этой категории и всех её дочерних.
- В аналитике и транзакциях селекты категорий получили tooltips с информацией о вложенных категориях.

## Изменения схемы

- Применена миграция `V13__payment_document_next_payment.sql`. Существующие базы обновляются автоматически при запуске; резервная копия создаётся до применения схемы через уже действующий механизм (`VACUUM INTO`).
- Остальные таблицы не изменились.

## Совместимость и обновление

- Существующие базы при запуске обновляются с V12 до V13 автоматически; резервная копия создаётся до применения схемы.
- Поле `next_payment_amount` не влияет на существующие записи: все значения по умолчанию `NULL`.
- Старые записи доходов, расходов, накоплений и переводов не переписываются.

## Известные ограничения

- Размер следующего платежа не обновляется автоматически: пользователь фиксирует его вручную через форму «Следующий платёж».
- Нет автоматического расчёта следующего платежа на основе периодичности.
- Сборки не подписаны и не нотаризованы: Windows SmartScreen и macOS Gatekeeper могут показывать предупреждение о неизвестном издателе. Установщик в выпуск не входит.
- Визуальная проверка при 1280×720 и сборка под Windows в этой среде не выполнялись.
