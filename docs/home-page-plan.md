# План: стартовая страница «Главная»

Статус: реализовано (код, тесты и документация обновлены). Описание опирается на фактическое состояние репозитория (`crates/ui/src/gpui/shell.rs`, `transactions.rs`, `transfers.rs`, `settings.rs`, `docs/architecture.md`, `docs/page-actions-and-filters.md`, `docs/decisions.md`).

> Это план первоначальной реализации. Секция быстрых действий позже заменена двумя встроенными формами добавления дохода и расхода; актуальное состояние описано в [`home-quick-forms-plan.md`](home-quick-forms-plan.md).

## 1. Назначение

Новая вкладка «Главная» — навигационная стартовая страница:

- короткие описания разделов «Доходы», «Расходы», «Справочники» с переходом на них;
- быстрые действия: «Добавить доход», «Добавить расход», «Добавить перевод»;
- переход на все страницы приложения.

Страница не вводит финансовой семантики: без сумм, итогов, балансов и отчётов. Формулы «На руках» и «Баланс» не согласованы (`AGENTS.md`, раздел 9.4), поэтому на «Главной» они не выводятся.

## 2. Принятые решения

| Решение | Значение |
|---|---|
| Название и позиция | Вкладка «Главная», первая в `PageTab::ALL`, открывается при запуске (сейчас стартовой является «Доходы») |
| Источник данных | Таблиц и фильтров нет; обращение к БД — только один запрос доступности счетов для «Добавить перевод» при активации вкладки, без обращений на каждом кадре |
| Переходы | Переиспользуются уже созданные `Entity` страниц в `AppShell`; новая вкладка не дублирует функциональность существующих страниц |
| Быстрые действия | Открывают существующие модальные формы страниц: доход и расход — `TransactionsPage`, перевод — `TransfersPage`. Повторно используются существующие диалоги, валидация и тексты ошибок |
| Разметка | Заголовок по общему шаблону `docs/page-actions-and-filters.md` («Shared Header Pattern»): название слева, 24 px, полужирный; кнопок уровня страницы нет, действия вынесены в секции |
| Миграции и БД | Не требуются; изменения только в `finance-ui` |
| Оформление | Только русские подписи; цвета через `cx.theme()`, как на остальных страницах |

Уточнение к запросу: в перечне быстрых действий «Добавить расход» был указан дважды. Согласованный набор — «Добавить доход», «Добавить расход», «Добавить перевод» плюс блок переходов на все страницы.

## 3. Структура страницы

1. Заголовок «Главная».
2. Секция «Быстрые действия»: три кнопки в строку — «Добавить доход», «Добавить расход», «Добавить перевод»; иконка `IconName::Plus` (значок уже встроен, см. тест `bundled_plus_icon_is_available` в `shell.rs`), вариант Primary, размер Large, как на страницах операций.
3. Секция «Разделы»: три карточки с названием-ссылкой и коротким описанием:
   - «Доходы» — учёт поступлений: дата, категория, сумма в RUB или USD, комментарий; фильтры по периоду, категории, банку, карте и поиск; итоги отдельно по валютам.
   - «Расходы» — то же для списаний, дополнительно указывается место траты; привязка к карте влияет на остаток дебетовой карты.
   - «Справочники» — банки, категории доходов и расходов, места трат, валюты и основная валюта; используемые записи защищены от удаления, неактивные сохраняются в истории.
4. Секция «Все страницы»: ссылки на все разделы приложения — Доходы, Расходы, Накопления, Переводы, Платёжные карты, Анализ, Справочники, Настройки — единой сеткой с переносом по ширине.
5. Состояния: собственных данных у страницы нет; недоступное действие показывается отключённой кнопкой с пояснением, а не скрывается и не выполняется «впустую».
Требование 1280×720: сетка переносится по ширине, горизонтальная прокрутка не используется; проверяется запуском приложения.

## 4. Изменения в коде

### 4.1. Новый файл `crates/ui/src/gpui/home.rs`

Только данные и чистые функции, без состояния и без отдельной GPUI-сущности:

- `pub(crate) enum HomeAction` — `OpenIncomes`, `OpenExpenses`, `OpenDirectories`, `OpenSavings`, `OpenTransfers`, `OpenPaymentDocuments`, `OpenAnalysis`, `OpenSettings`, `NewIncome`, `NewExpense`, `NewTransfer`.
- `pub(crate) const fn home_action_tab(action: HomeAction) -> PageTab` — отображение действия во вкладку; для `New*` — вкладка соответствующей страницы.
- `pub(crate) struct HomeLink { pub(crate) title: &'static str, pub(crate) description: &'static str, pub(crate) action: HomeAction }` и функции `described_sections() -> [HomeLink; 3]`, `all_page_links() -> [HomeLink; 8]`.
- `pub(crate) struct QuickAction { pub(crate) label: &'static str, pub(crate) action: HomeAction }` и `quick_actions() -> [QuickAction; 3]`.
- При необходимости — вспомогательная функция построения карточки, получающая обработчик нажатия как аргумент (`impl Fn(HomeAction)`), чтобы разметка оставалась в `AppShell`, где доступен `cx.listener`.

Описания разделов — константы интерфейса в этом файле; перенос в `finance-core` не требуется.

### 4.2. `crates/ui/src/gpui/shell.rs`

- В `PageTab` добавить вариант `Home` первым; расширить `ALL` с 8 до 9; в `title()` — «Главная».
- Приватный метод `AppShell::activate(&mut self, tab: PageTab, window, cx)`: устанавливает `self.active` и вызывает существующий `reload` нужной страницы — перенести туда текущий `match` из обработчика `TabBar::on_click`.
- Приватный метод `AppShell::run_home_action(&mut self, action: HomeAction, window, cx)`: сначала `activate(...)`, затем для `New*` — вызов создания записи на странице-получателе, например `this.income.update(cx, |page, cx| page.create_new(window, cx))`, аналогично для расходов и переводов.
- Отрисовка вкладки — приватный `AppShell::render_home(&mut self, cx) -> AnyElement`, собирающий разметку из данных `home.rs`; обработчики — `cx.listener` с вызовом `run_home_action`.
- Стартовая вкладка при запуске: `active: PageTab::Home`.
- Если девять вкладок не помещаются в 1280 px, использовать возможности `TabBar` — `track_scroll` и/или `.menu(true)` (меню переполнения), а не сокращать названия. Фактическая потребность проверяется запуском.
- Доступность «Добавить перевод»: при активации «Главной» один раз прочитать счета (`finance_db::list_payment_documents`, `finance_db::list_savings`) и сохранить флаг в `AppShell`; при отсутствии подходящих счетов кнопка отключена с пояснением «Добавьте карту или накопление; кредитные карты не участвуют».

### 4.3. `crates/ui/src/gpui/transactions.rs`

- Добавить `pub(crate) fn create_new(&mut self, window: &mut Window, cx: &mut Context<Self>)`, делегирующий существующему приватному `open_form(None, window, cx)`. Поведение формы, валидация и предупреждение о необходимости категории остаются без изменений.

### 4.4. `crates/ui/src/gpui/transfers.rs`

- Добавить `pub(crate) fn create_new(&mut self, window: &mut Window, cx: &mut Context<Self>)`: сначала `self.reload_accounts(window, cx)` (актуальные карты и накопления, ошибка показывается так же, как на странице), затем существующий `begin_new(window, cx)`.
- Условие доступности перевода вынести в чистую функцию, пригодную для проверки из `AppShell`, с тем же правилом, что на странице переводов: кредитные карты не учитываются, счета без явно заданной валюты не учитываются.

## 5. Тесты (модульные, рядом с кодом, по принятому в проекте образцу)

`home.rs`:

- `described_sections()` содержит ровно три раздела с названиями «Доходы», «Расходы», «Справочники»; описания непустые и не длиннее установленного предела, текст на русском;
- каждый `HomeAction` отображается ровно в одну вкладку; навигационных действий ровно восемь и покрыты все вкладки, кроме «Главной»;
- быстрых действий ровно три, подписи «Добавить доход», «Добавить расход», «Добавить перевод»; действие `New*` ведёт на вкладку соответствующей операции.

`shell.rs`:

- `PageTab::Home.title() == "Главная"`;
- `PageTab::ALL` содержит 9 вкладок, «Главная» первая, названия уникальны.

`transfers.rs`:

- условие доступности перевода: только кредитные карты — недоступно; две карты с совпадающей валютой — доступно; накопление без валюты не учитывается.

Ручная проверка: запуск `rustup run stable cargo run -p finance-app`, переход со «Главной» на каждый раздел, открытие трёх форм быстрых действий, сохранение и отмена, раскладка при 1280×720.

## 9. Открытые вопросы и риски

1. Девять вкладок в 1280 px: возможное переполнение `TabBar`. Проверяется запуском; при необходимости — меню переполнения и прокрутка.
2. Стартовая вкладка: «Главная» вместо «Доходы» меняет привычный вход. Сохранение последней открытой вкладки между запусками потребовало бы отдельного решения (настройка в `app_settings`) и в этот план не входит.
3. Открытие формы из быстрого действия: форма модальная и принадлежит странице, поэтому сначала активируется вкладка, затем открывается форма; проверить, что диалог не перекрывается и не теряется при переключении.
4. «Добавить перевод» при отсутствии счетов: выбрано отключение с пояснением; альтернатива — разрешать нажатие и показывать сообщение страницы переводов.
5. Описания разделов — тексты интерфейса; при изменении поведения страниц их нужно синхронизировать.
