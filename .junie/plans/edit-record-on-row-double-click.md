# Requirements

### Цель
Двойной клик по строке таблицы открывает именно эту запись в существующей форме редактирования — так же, как кнопка «Изменить».

### Область действия
- Поддержать редактируемые строки доходов и расходов, накоплений, платёжных карт, переводов, цен и справочников (категории, банки, места покупок, валюты).
- Не добавлять редактирование для таблиц аналитических агрегатов, у которых нет формы записи.
- Сохранить кнопки действий и выделение/копирование текста; двойной клик по тексту может одновременно выделить слово и вызвать редактирование.
- Не менять доменную логику, базу данных и схему.

### Поведение
Обработчик должен открыть запись, на которую пришёлся двойной клик, даже после сортировки или фильтрации. В четырёх таблицах справочников включение события строки также включит стандартный выбор/подсветку строки при одиночном клике.

# Technical Design

### Текущее устройство
Таблицы используют `gpui_kit::DataTable` и `TableState`; в `gpui-kit 0.10.0` есть событие `TableEvent::DoubleClickedRow(usize)`, но оно не испускается при `.row_selectable(false)`. Такое отключение задано для четырёх таблиц в `directories.rs`. Подписки на таблицы уже используются для сохранения ширины столбцов. Редактирование сейчас вызывается обработчиками кнопок «Изменить» в делегатах таблиц. Текстовые ячейки обёрнуты в `SelectableText` из `crates/ui/src/gpui/selectable.rs`.

### Ключевые решения
- Использовать `DoubleClickedRow`, а не `DoubleClickedCell`: действие относится ко всей строке, а не к конкретному столбцу.
- Получать запись из текущей последовательности строк делегата таблицы и передавать существующему методу редактирования её стабильный ID/код. Не использовать индекс видимой строки как идентификатор: делегаты могут сортировать строки независимо от списка страницы.
- Для четырёх таблиц справочников включить выбор строки, необходимый для `DoubleClickedRow`; одиночный клик будет выбирать и подсвечивать строку. Существующий слой выделения текста не менять.

### Изменения по компонентам
- `TransactionsTable` в `transactions.rs`: двойной клик открывает доход или расход через существующий поток редактирования с учётом `TransactionKind`.
- `SavingsTable` в `savings.rs`, `CardsTable` в `payment_documents.rs` и `TransfersTable` в `transfers.rs`: вызвать соответствующие существующие методы начала редактирования.
- `PricesTable` в `prices.rs`: открыть форму цены для записи текущей строки.
- Таблицы `CategoriesTable`, `BanksTable`, `ExpensePlacesTable` и `CurrenciesTable` в `directories.rs`: включить событие строки и вызвать существующие методы форм справочников.
- Добавить обработку рядом с уже существующими подписками на ширину колонок; оставить кнопки действий и `selectable.rs` без изменения поведения.

### Риски
Главный риск — несоответствие индекса события записи после сортировки/фильтрации; его предотвращает чтение текущей строки из делегата и переход к стабильному ID. Включение выбора строк в справочниках меняет одиночный клик с «без выбора» на выбор с подсветкой.

# Testing

### Проверки
- Добавить или обновить unit-тесты преобразования индекса строки делегата в ID/код записи, если для маршрутизации выделяется общий вспомогательный метод; проверить корректность при сортировке и отсутствие результата для недопустимого индекса.
- Запустить `cargo test -p finance-ui --locked` и `cargo check --workspace --all-targets --locked`.
- Проверить сценарии двойного клика по данным после сортировки/фильтрации и по строкам справочников; убедиться, что существующее выделение текста и кнопки действий сохранены.

# Delivery Steps

### ✓ Step 1: Подключить двойной клик в таблицах основных записей
Двойной клик в таблицах финансовых записей открывает форму редактирования выбранной строки.
- Добавить обработку `TableEvent::DoubleClickedRow` в `transactions.rs`, `savings.rs`, `payment_documents.rs`, `transfers.rs` и `prices.rs` рядом с существующими подписками таблиц.
- Получать строку из актуального делегата таблицы, извлекать стабильный ID и вызывать тот же метод формы, что используется кнопкой «Изменить».
- Сохранить кнопки действий и существующий `SelectableText`; добавить тесты маршрутизации строки в ID там, где для этого создаётся вспомогательная функция.
- Проверить сортируемые/отфильтрованные строки тестами и выполнить `cargo test -p finance-ui --locked`.

### ✓ Step 2: Добавить редактирование двойным кликом в справочниках и проверить сборку
Двойной клик по редактируемой строке справочника открывает соответствующую форму, а весь UI crate проходит проверку.
- Подключить `DoubleClickedRow` для `CategoriesTable`, `BanksTable`, `ExpensePlacesTable` и `CurrenciesTable` в `directories.rs`.
- Включить `row_selectable` для этих таблиц, чтобы GPUI испускал событие; сохранить маршрутизацию через данные делегата к существующим методам редактирования.
- Убедиться, что выбор строки при одиночном клике и выделение текста при двойном клике не мешают открытию формы, а таблицы аналитики не затронуты.
- Выполнить `cargo check --workspace --all-targets --locked`.
